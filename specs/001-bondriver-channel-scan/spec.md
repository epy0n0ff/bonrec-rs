# Feature Specification: BonDriverチャンネルスキャン

**Feature Branch**: `001-bondriver-channel-scan`
**Created**: 2025-12-01
**Status**: Draft
**Input**: User description: "BonDriverを使って全てのチャンネルをスキャンしてチャンネル情報を取得出力するものを作りたい"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 全チャンネルスキャンの実行 (Priority: P1)

ユーザーは、BonDriverを使用して全ての利用可能なチャンネルをスキャンし、チャンネル情報の一覧を取得したい。これにより、録画やリアルタイム視聴の設定に必要なチャンネル情報を把握できる。

**Why this priority**: チャンネルスキャンはこの機能の中核であり、他の全ての機能の基盤となる。チャンネル情報がなければ録画設定も視聴もできない。

**Independent Test**: BonDriverファイルを指定してスキャンを実行し、検出されたチャンネルの一覧が出力されることを確認できる。

**Acceptance Scenarios**:

1. **Given** BonDriverファイルが利用可能な状態, **When** ユーザーがスキャンコマンドを実行する, **Then** 全てのチャンネルがスキャンされ、各チャンネルの情報が表示される
2. **Given** スキャン対象として地上波、BS、CSが存在する状態, **When** スキャンを実行する, **Then** 各放送波のチャンネルが網羅的にスキャンされる
3. **Given** スキャン中の状態, **When** 進捗状況を確認する, **Then** 現在のスキャン進捗（何チャンネル目/全体など）が表示される

---

### User Story 2 - チャンネル情報の出力フォーマット選択 (Priority: P2)

ユーザーは、取得したチャンネル情報を複数のフォーマット（標準出力、ファイル出力）で出力したい。これにより、他のアプリケーションでの利用や記録保存が容易になる。

**Why this priority**: 基本的なスキャン機能が動作した後、出力形式の柔軟性は実用性を高める重要な機能。

**Independent Test**: スキャン結果を指定したフォーマットで出力し、正しい形式で情報が含まれていることを確認できる。

**Acceptance Scenarios**:

1. **Given** スキャンが完了した状態, **When** ユーザーが標準出力を選択する, **Then** チャンネル情報がコンソールに表示される
2. **Given** スキャンが完了した状態, **When** ユーザーがファイル出力を指定する, **Then** 指定されたパスにチャンネル情報ファイルが作成される

---

### User Story 3 - 特定放送波のみのスキャン (Priority: P3)

ユーザーは、全放送波ではなく特定の放送波（地上波のみ、BSのみ、CSのみ）を選択してスキャンしたい。これにより、必要な情報のみを効率的に取得できる。

**Why this priority**: フル機能ではあるが、基本的なスキャン機能の拡張であり、必須ではない。

**Independent Test**: 放送波を指定してスキャンを実行し、指定した放送波のチャンネルのみがスキャンされることを確認できる。

**Acceptance Scenarios**:

1. **Given** 複数の放送波が利用可能な状態, **When** ユーザーが地上波のみを指定してスキャンする, **Then** 地上波のチャンネルのみがスキャンされる
2. **Given** 複数の放送波が利用可能な状態, **When** ユーザーがBS/CSを指定してスキャンする, **Then** BS/CSのチャンネルのみがスキャンされる

---

### Edge Cases

- BonDriverファイルが見つからない、または読み込めない場合は、明確なエラーメッセージを表示する
- チューナーデバイスが使用中または利用不可の場合は、エラーメッセージと対処方法を表示する
- スキャン中にシグナルが弱い/受信不可のチャンネルは、その旨を記録して次のチャンネルに進む
- スキャン中にユーザーが中断を要求した場合は、それまでに取得した情報を保持するオプションを提供する
- 同一チャンネルが複数のBonDriverから検出された場合は、重複を排除し、取得元BonDriver情報を全て記録する（どのチューナーからアクセス可能か把握できるようにする）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは指定されたBonDriverファイル（複数指定可能）を読み込み、チューナーデバイスとの通信を確立できなければならない
- **FR-002**: システムは全てのチューニングスペース（地上波、BS、CS等）を列挙できなければならない
- **FR-003**: システムは各チューニングスペース内の全てのチャンネルをスキャンできなければならない
- **FR-004**: システムは各チャンネルについて以下の情報を取得できなければならない：
  - 物理チャンネル番号
  - チューニングスペース名
  - チャンネル名（BonDriverから取得可能な場合）
  - サービスID（放送ストリームから取得可能な場合）
  - ネットワークID（放送ストリームから取得可能な場合）
  - トランスポートストリームID（放送ストリームから取得可能な場合）
  - 放送局名（SI情報から取得可能な場合）
- **FR-005**: システムはスキャン進捗をユーザーに表示しなければならない
- **FR-006**: システムはスキャン結果を標準出力に表示できなければならない
- **FR-007**: システムはスキャン結果をファイルに出力できなければならない
- **FR-008**: システムは特定のチューニングスペースのみをスキャン対象として選択できなければならない
- **FR-009**: システムはスキャン中のエラー（受信不可、タイムアウト等）を適切に処理し、他のチャンネルのスキャンを継続できなければならない
- **FR-010**: システムはユーザーの中断要求を受け付け、安全にスキャンを停止できなければならない
- **FR-011**: システムはSI情報取得のタイムアウト時間をユーザーが指定できなければならない（デフォルト5秒）
- **FR-012**: システムは複数のBonDriverが指定された場合、それぞれを順次スキャンし、結果を統合して出力できなければならない

### Key Entities

- **BonDriver**: チューナーデバイスとの通信を抽象化するドライバーインターフェース。対応する物理チューナーと、利用可能なチューニングスペースを持つ。
- **TuningSpace（チューニングスペース）**: 放送波の種類を表す。地上波、BS、CS等。複数のチャンネルを含む。
- **Channel（チャンネル）**: 特定の周波数/トランスポンダを表す。物理チャンネル番号、チューニングスペースへの所属、取得元BonDriver一覧（複数可）を持つ。
- **Service（サービス）**: 一つのチャンネル内で放送される番組サービス。サービスID、放送局名を持つ。複数のサービスが一つのチャンネルに存在しうる。
- **ScanResult（スキャン結果）**: スキャン実行の結果。検出されたチャンネルとサービスの一覧、スキャン日時、使用したBonDriver情報を含む。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは1回のコマンド実行で、利用可能な全チャンネルの情報を取得できる
- **SC-002**: スキャン結果には、録画・視聴設定に必要な情報（チャンネル識別子、放送局名）が含まれる
- **SC-003**: スキャン中に1つのチャンネルでエラーが発生しても、他のチャンネルのスキャンは正常に継続される
- **SC-004**: ユーザーはスキャン進捗を確認でき、現在何チャンネル目をスキャン中か把握できる
- **SC-005**: スキャン結果は他のアプリケーションで利用可能な形式で出力できる

## Clarifications

### Session 2025-12-01

- Q: デフォルトの出力フォーマットは何か？ → A: JSON形式をデフォルトとする
- Q: 対象プラットフォームは？ → A: Windowsのみ対象
- Q: SI情報取得のタイムアウト時間は？ → A: ユーザーが指定可能（デフォルト5秒）
- Q: 複数BonDriverの扱いは？ → A: 複数のBonDriverを同時に指定してまとめてスキャン可能
- Q: 重複チャンネルの統合方法は？ → A: 重複を排除するが、取得元BonDriver情報を全て記録

## Constraints

- **対象プラットフォーム**: Windowsのみ（BonDriver DLLの動的ロードを使用）

## Assumptions

- BonDriverインターフェースを実装したDLLファイルがユーザーのWindows環境に存在する
- チューナーデバイスがWindowsに正しくインストールされ、動作可能な状態にある
- デフォルト出力フォーマットはJSON形式とする（構造化データの表現に最適で、ネスト構造を自然に表現可能）
- SI情報（放送局名等）の取得は、放送ストリームを受信して行う（タイムアウトはユーザー指定可能、デフォルト5秒）
- スキャン時間は放送波の種類やチャンネル数に依存するが、ユーザーは待機できる
